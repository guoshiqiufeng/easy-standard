# 03 Vue 3 开发规范

[返回首页](../README.md)

Vue 3 为固定技术方向；TypeScript、路由库、状态库、UI 库和构建工具由项目登记。推荐单文件组件与 Composition API；使用单文件组件及 Composition API 时推荐 `<script setup>`。JavaScript 项目同样需要清晰的接口模型、运行时校验和自动检查。

## 强制规则

| 编号 | 适用 | 执行要求 | 检查与证据 | 责任 |
| --- | --- | --- | --- | --- |
| VUE-001 | 所有前端项目 | 登记 Vue、运行时、包管理器、主要库的版本及支持范围；提交依赖锁文件，CI 按锁文件安装 | 基线、锁文件、构建日志 | 前端负责人 |
| VUE-002 | 页面与组件 | 按业务功能组织；页面负责用例编排，组件职责单一；公共组件有清晰 props、events 和 slots 契约 | 目录与组件评审 | 开发者 |
| VUE-003 | 响应式数据 | 不直接修改 props；状态归属明确；派生状态用计算逻辑；订阅、定时器、监听和外部资源按生命周期清理 | 评审、卸载测试 | 开发者 |
| VUE-004 | 列表与表单 | 列表使用稳定业务 key；表单覆盖必填、范围、长度及跨字段校验；保留服务端校验并展示字段级错误 | 组件、表单测试 | 开发者 |
| VUE-005 | 请求与异常 | 统一处理超时、取消、错误解码和登录失效；区分无权限、资源不存在、冲突与服务异常；展示 traceId 便于排障 | 请求适配测试 | 前端负责人 |
| VUE-006 | 异步交互 | 明确加载、空数据、失败、重试、成功状态；重复提交有前端保护和后端幂等；处理旧请求覆盖新结果 | 交互和竞态测试 | 开发者 |
| VUE-007 | 权限界面 | 路由、按钮按权限展示，但后端必须独立授权；禁止把前端过滤当作数据隔离 | 越权测试、代码评审 | 前后端负责人 |
| VUE-008 | 安全与配置 | 不在前端包、环境变量或存储中放服务端秘密；不拼接不可信 HTML；需要富文本时使用经评审的净化方案 | 构建产物抽查、安全测试 | 前端负责人 |
| VUE-009 | 界面可用性 | 表单有标签，键盘可完成核心操作；错误提示可感知，焦点可见；颜色不是唯一状态信号 | 键盘与可访问性检查 | 开发者 |
| VUE-010 | 浏览器与性能 | 登记支持的浏览器和设备；设置首屏、资源体积与关键交互的测量预算，避免无界列表渲染 | 兼容性与性能报告 | 前端负责人 |
| VUE-011 | 格式和检查 | 统一 lint 与格式规则；采用 TypeScript 时执行类型检查；禁止用无说明的禁用注释或类型逃逸消除错误 | CI 日志、例外说明 | 开发者 |

## 推荐结构

```text
src/
  app/                 应用初始化、路由和全局配置
  features/orders/     订单页面、局部组件、用例与接口
  components/          无业务归属的复用组件
  composables/         可复用的响应式逻辑
  services/            HTTP 适配、错误转换
  styles/              设计变量和基础样式
```

路由状态用于可分享或可恢复的筛选条件；组件本地状态用于临时交互；共享状态只保存多处使用且有明确生命周期的数据。不要复制可以从其他状态推导的数据。权限信息和个人数据在退出或切换身份时清理，缓存也必须按用户／租户隔离。

## 请求与数据边界

- 使用 [API 约定](04-api.md)；业务 ID 保持字符串，禁止通过 `Number(id)` 或 `parseInt(id)` 转换。
- 金额保持十进制字符串；展示格式与计算分开，客户端金额不作为服务端结算依据。
- 时间点按用户／项目时区展示，提交时保留偏移；纯日期不做隐式 UTC 转换。
- 使用 Cookie 认证时落实 CSRF 与 Cookie 策略；使用令牌时通过安全评审确定存储、过期、刷新和注销方案。
- 自动重试只用于明确安全或幂等的操作；刷新凭证避免并发请求循环刷新；鉴权失败后的原操作是否重放需确认幂等性。

## 正反例

```vue
<!-- 错误：列表排序后索引 key 可能将组件状态关联到错误记录。 -->
<OrderRow v-for="(order, index) in orders" :key="index" :order="order" />

<!-- 正确：稳定业务 ID 保持字符串。 -->
<OrderRow v-for="order in orders" :key="order.id" :order="order" />
```

反例：只隐藏“删除”按钮，却允许其他用户直接调用删除接口。正确做法是后端同时验证操作权限和目标资源归属，前端只承担体验上的权限展示。

样式推荐使用作用域或命名空间，统一颜色、间距和字号变量；大型页面按路由拆包，图片按实际场景加载。是否引入服务端渲染、微前端或离线能力由 ADR 决定。
