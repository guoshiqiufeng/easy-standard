# 06 安全规范

[返回首页](../README.md)

本章为工程安全基线。行业专属法规、合规认证与保留期限由项目另外确认，不因采用本规范就视为已满足认证要求。

## 强制规则

| 编号 | 适用 | 执行要求 | 检查与证据 | 责任 |
| --- | --- | --- | --- | --- |
| SEC-001 | 需登录的系统 | 使用经评审的身份方案；凭证有过期、撤销和退出策略；密码使用专用密码哈希算法，不保存可逆或明文密码 | 认证设计、登录生命周期测试 | 安全负责人 |
| SEC-002 | 受保护资源与操作 | 后端逐次验证身份、操作权限和资源范围；默认拒绝；覆盖查询、导出、文件、任务与管理入口 | 横向／纵向越权测试 | 后端负责人 |
| SEC-003 | 不可信输入输出 | 校验类型、长度、范围、数量和格式；使用参数化查询、上下文编码；避免不可信反序列化与命令拼接 | 安全用例、扫描与评审 | 开发者 |
| SEC-004 | 浏览器访问 | 明确 CORS 来源；凭证请求不使用任意来源；Cookie 认证配置 Secure、HttpOnly 和适当 SameSite，并实施 CSRF 防护 | 跨站请求与会话测试 | 前后端负责人 |
| SEC-005 | 环境与密钥 | 生产秘密不进入仓库、镜像、前端包、日志或公开文档；按最小权限注入、轮换和撤销；开发测试生产隔离 | 密钥扫描、权限和轮换记录 | 运维负责人 |
| SEC-006 | 网络与管理面 | 外部业务流量使用 TLS；数据库、指标、管理接口不直接对公网开放；管理访问有身份与审计 | 部署审查、网络验证 | 运维负责人 |
| SEC-007 | 上传、下载、URL 抓取 | 限制大小、类型和数量，验证实际内容，隔离存储；检查路径穿越与对象授权；出站地址限制防 SSRF | 恶意文件、路径和出站测试 | 后端负责人 |
| SEC-008 | 敏感操作与数据 | 关键操作记录操作者、时间、动作、对象、结果、关联标识；敏感数据按用途脱敏，审计访问受限并防未授权篡改 | 审计样本、访问测试 | 安全负责人 |
| SEC-009 | 依赖与镜像 | 扫描已知漏洞、秘密和许可证风险；登记确认结果、影响范围、修复或缓解期限；确认可利用且无缓解的高危问题阻止发布 | 扫描报告、修复或有效例外 | 技术负责人 |
| SEC-010 | 滥用风险入口 | 对登录、验证码、昂贵查询和敏感写操作设置合适限制；防止日志或错误暴露秘密，限制请求体规模 | 限流、错误与泄露测试 | 技术负责人 |
| SEC-011 | 安全事件 | 立即按事件机制控制影响，保留证据、轮换受影响凭证并追踪处置；避免在公开渠道扩散秘密 | 事件记录、闭环证据 | 安全负责人 |

## 评审重点

身份来自验证后的会话或令牌，不接受客户端任意传入的 userId／tenantId 作为授权依据。资源 ID 难以猜测不能替代权限检查。错误可统一隐藏跨用户资源是否存在；测试需确认列表、详情、修改与导出保持一致。

对资金、权限、批量删除等高风险操作，项目根据实际影响登记二次确认、重认证或双人审批需求。外部 URL 抓取应检查协议、解析后的目标地址和重定向，禁止访问未允许的内网或元数据服务。文件存储使用服务端生成的名称，上传目录不能执行脚本。

## 漏洞处理默认时限

以下是团队初始处理目标，项目应按值守能力和业务风险登记：确认可利用的严重或高危问题发现后立即分派并控制暴露，24 小时内给出处置方案；其他高危 7 天、中危 30 天、低危 90 天内修复或取得有期限的例外。时限从确认时间计算，不代表允许带着可利用且无有效缓解的高危漏洞发布。
