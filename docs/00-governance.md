# 00 总则与治理

[返回首页](../README.md)

## 适用范围与优先级

适用于团队新建和维护的 Java＋Vue 3 常规业务项目。项目可以使用不同 Java 版本、后端框架、数据库、构建工具和前端语言，但须登记受维护版本、兼容性、选型理由及升级负责人。默认模块化单体，避免为形式而引入微服务。

项目采用本规范的明确版本。外部法规或合同的实际要求由有职责的人员确认后纳入项目基线；项目可以增加更严格的要求。与本规范冲突时，通过 `GOV-004` 处理，不得默默覆盖。阿里巴巴手册强制条款为 Java 基线；本文只整理重点，不能将“未列出”等同于“不适用”。

## 强制规则

| 编号 | 适用 | 执行要求 | 检查与证据 | 责任 |
| --- | --- | --- | --- | --- |
| GOV-001 | 所有项目 | 登记规范版本、技术版本、职责、环境、门槛、业务与恢复目标；首次开发前评审，重大变更时更新 | 已评审的技术基线、变更记录 | 项目负责人 |
| GOV-002 | 所有交付 | 需求、设计、代码、测试、制品、发布可相互追溯；保留验收结论 | 需求号到发布版本的关联记录 | 项目负责人 |
| GOV-003 | 所有团队 | 每个阶段有明确负责人和评审人；允许一人多角色，代码作者不得作为唯一代码审批人 | 角色表、审批记录 | 项目负责人 |
| GOV-004 | 不满足适用强制项 | 发布或合并前取得例外，记录规则号、范围、风险、补偿控制、整改负责人、批准人、到期日；到期未关闭重新阻断 | 例外单及到期检查记录 | 技术负责人 |
| GOV-005 | 规范维护 | 规则编号稳定且不复用；变更须评审，记录版本、兼容影响、通知方式和迁移期限 | 变更记录、评审结论 | 规范维护者 |
| GOV-006 | 存量项目接入 | 完成差距清单，区分历史问题与新增问题；历史豁免须有范围和期限，不允许扩大 | 差距清单、整改计划 | 技术负责人 |
| GOV-007 | 项目退役 | 明确依赖方迁移、数据处置、权限与密钥撤销、资源释放、文档归档，并取得验收 | 退役记录、执行证据 | 项目负责人 |

不得用例外批准明文生产密钥入库、故意关闭必要授权，或带着已确认可利用且无有效缓解的高危漏洞上线。发现此类问题先修复或隔离，再交付。一般例外由技术负责人批准；安全项增加安全负责人会签，数据与业务风险增加对应责任人会签；申请人不能单独批准自己的例外。

## 职责与阶段产物

| 阶段 | 主责 | 审核／参与 | 必须产物与完成条件 |
| --- | --- | --- | --- |
| 需求 | 产品／业务负责人 | 开发、测试 | 需求范围、验收场景、优先级、非功能目标确认 |
| 设计 | 技术负责人 | 前后端、测试、运维、安全 | 设计、接口、数据、风险与决策评审通过 |
| 开发 | 开发负责人 | 独立代码评审人 | 实现、测试、契约和文档同步，合并门槛通过 |
| 测试 | 测试负责人 | 开发、业务负责人 | 测试报告、缺陷结论、业务验收 |
| 发布 | 发布负责人 | 技术、测试、运维 | 固定制品、发布与恢复方案、审批和验证证据 |
| 运行 | 运维负责人 | 技术、业务负责人 | 仪表盘、值守安排、备份、恢复演练、事件记录 |
| 退役 | 项目负责人 | 业务、数据、运维、安全 | 使用方迁移和数据处置验收 |

## 推荐节奏与治理指标

每季度检查规范与工具适配，每月查看交付与运行情况。指标包括变更失败率、故障恢复耗时、关键缺陷逃逸、例外逾期、恢复演练达标情况。度量用于改进系统，不按个人提交量或缺陷数量排名。

新增要求先在一个项目试用，明确收益和成本后推广。规范主版本表示不兼容要求变化，次版本表示向后兼容新增，修订版本用于澄清与纠错。项目可以暂时停留旧版，但必须登记升级时间；紧急安全修订单独规定期限。
