# 09 构建、环境与发布

[返回首页](../README.md)

部署默认 Linux＋Docker；Compose 用于单机和可接受单机故障边界的环境。Compose 本身不是跨主机高可用方案。项目的恢复目标超出单机能力时，必须增加冗余与调度能力并形成 ADR，可演进至 Kubernetes 或其他平台。

## 强制规则

| 编号 | 适用 | 执行要求 | 检查与证据 | 责任 |
| --- | --- | --- | --- | --- |
| REL-001 | 所有构建 | 登记编译与运行工具版本，固定依赖解析，使用干净环境构建；保留提交、依赖和制品关联 | 构建记录、依赖锁或版本清单 | 开发负责人 |
| REL-002 | 部署环境 | 区分开发、测试、预生产和生产；环境配置与制品分离；生产数据和秘密不向低环境复制 | 环境矩阵、配置审核 | 运维负责人 |
| REL-003 | CI／CD | 执行检查、测试、扫描、构建和发布验证，适用强制项失败阻断；例外可追踪且未过期 | 流水线报告 | 技术负责人 |
| REL-004 | 发布制品 | 构建一次，按不可变摘要逐级提升；记录代码、依赖、镜像、配置与迁移版本；禁止使用浮动 latest 发布 | 发布清单、摘要核对 | 发布负责人 |
| REL-005 | 容器运行 | 使用受维护的固定基础镜像；默认非 root，限制资源和权限；配置持久化、健康检查、日志轮转、重启和优雅退出 | 镜像与 Compose 审查、环境验证 | 运维负责人 |
| REL-006 | 生产发布 | 有范围、影响、窗口、负责人、验收指标、审批、回滚触发和恢复步骤；执行前确认最新备份与兼容性 | 发布方案、检查清单 | 发布负责人 |
| REL-007 | 数据变更 | 迁移单独受控执行，检查新旧应用兼容；明确不可逆步骤及恢复方案，不能把应用回滚当成数据回滚 | 迁移演练、兼容测试 | 数据负责人 |
| REL-008 | 发布验证 | 先验证就绪、关键业务与错误率，再扩大流量；失败停止推进并按阈值回滚或恢复 | 冒烟报告、监控记录 | 发布负责人 |
| REL-009 | 发布结束 | 记录实际版本、开始结束时间、结果、异常和跟踪项；失败发布复盘，紧急修复回合主线 | 发布记录、回合记录 | 发布负责人 |

## 平台中立的流水线契约

| 阶段 | 输入 | 必需行为与产物 | 阻断条件 |
| --- | --- | --- | --- |
| 获取 | 固定提交、已登记工具版本 | 清洁检出、依赖恢复、版本与来源记录 | 来源或版本不可确认 |
| 检查 | 源码和契约 | Java 规则映射检查、前端 lint／类型、密钥及依赖扫描、接口差异 | 适用强制项失败或无有效例外 |
| 测试 | 代码和测试环境 | 单元、组件、受影响集成与契约；覆盖率报告 | 必需测试失败、采用的门槛未达标 |
| 制品 | 已验证提交 | 构建应用与镜像、依赖／许可证清单、摘要 | 构建失败或高危安全底线未满足 |
| 预生产 | 同一制品、配置、迁移 | 数据变更演练、回归、冒烟及适用专项 | 验收未通过 |
| 生产 | 已批准清单 | 部署、必要迁移、就绪检查、业务与指标验证 | 到达停止／回滚阈值 |
| 归档 | 实际执行证据 | 发布结果、监控、异常与后续项 | 证据缺失则发布任务不算完成 |

工具和具体命令填写技术基线，命令必须能产生可判定的退出状态；不能使用忽略失败或把空报告判为成功的处理。扫描误报要有复核和受控排除，不能全局关闭检查。

## Docker 与 Compose 落地要求

前后端可以独立镜像，后端容器不暴露未鉴权管理接口。前端构建变量都视为公开配置。镜像中不保留构建凭证，部署凭证只允许拉取所需制品。运行时文件写入目录明确，临时空间有限额；持久化数据和容器生命周期分离。

应用必须响应退出信号：先停止接受新请求，再处理在途任务、提交或回滚事务、释放资源。终止宽限时间大于正常请求退出时间并设上限。Docker 健康检查只标记状态，不自动保证健康实例替换或业务流量切换；外部探测和运行平台需承担恢复动作。

单机 Compose 更新默认声明维护窗口或经过验证的双实例代理切换方案，不承诺自动零停机。初始数据库就绪不等于运行期间始终可用；应用仍需超时、重连与告警。数据库的可靠备份必须离开宿主机故障域，命名卷不能代替备份。

## 回滚决策

发布方案给出量化阈值和观测窗口，例如“关键冒烟失败立即停止；5 分钟内服务端错误率超过基线阈值则回滚”。数值按项目基线填写。先确认数据仍兼容旧版本，再按已知摘要恢复应用与对应配置；迁移不可逆时执行已演练的前向修复或备份恢复流程，并告知数据影响。
