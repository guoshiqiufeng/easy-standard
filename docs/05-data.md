# 05 数据设计与管理

[返回首页](../README.md)

不指定数据库产品。关系数据库示例中的字段类型、事务隔离和索引语法须按实际产品和版本验证；使用非关系数据库时同样明确一致性、唯一性、并发与恢复语义。

## 强制规则

| 编号 | 适用 | 执行要求 | 检查与证据 | 责任 |
| --- | --- | --- | --- | --- |
| DATA-001 | 新增模型 | 明确实体、业务含义、主键、唯一约束、字段类型与长度、空值、默认值、时间语义、数据所有者 | 数据字典、模型评审 | 数据负责人 |
| DATA-002 | 关系表与查询 | 使用可读且一致的命名；关键约束由数据库或等效强一致机制保证；索引依据真实查询设计 | DDL、查询计划、重复数据测试 | 后端负责人 |
| DATA-003 | SQL 或查询构造 | 参数化传递值，动态列名和排序采用白名单；不返回无用列；禁止无界批量读取／写入 | 查询评审、扫描、性能测试 | 开发者 |
| DATA-004 | 多步骤写入 | 登记事务范围、隔离要求、锁顺序、并发控制和死锁处理；避免跨网络长事务 | 一致性与并发测试 | 后端负责人 |
| DATA-005 | 数据库变更 | 迁移脚本版本化且已评审；评估锁表、耗时、磁盘、旧版本兼容和恢复；禁止应用启动时无审核修改生产结构 | 迁移演练、发布方案 | 数据负责人 |
| DATA-006 | 缓存 | 定义键空间、用户／租户隔离、有效期、容量、失效和故障回退；明确一致性要求，不把无持久化保证的缓存当作唯一事实源 | 缓存设计、故障与隔离测试 | 后端负责人 |
| DATA-007 | 数据生命周期 | 标明数据分级、访问范围、保留期限、归档与删除机制；测试数据脱敏，导出可追踪 | 数据清单、权限与删除验证 | 数据负责人 |
| DATA-008 | 批处理、补偿、回填 | 定义批大小、检查点、幂等、限速、暂停、重启和核对方式；预先评估影响范围 | 试运行报告、核对记录 | 开发者 |
| DATA-009 | 审计与软删除 | 业务确需时才采用软删除；明确查询默认过滤、唯一约束、恢复、关联数据与最终清除；审计不随业务删除失控 | 生命周期与恢复测试 | 数据负责人 |

## 命名、精度与索引建议

推荐数据库表和字段使用小写 snake_case；外部 JSON 使用 lowerCamelCase，由映射层转换。金额使用十进制定点类型，登记精度、标度和币种；不要使用浮点列。时间点的存储类型、UTC 策略和驱动转换通过实际数据库测试验证。

业务唯一性依赖唯一约束，不能只用“先查不存在再插入”。索引服务于筛选、关联与排序；通过预估规模和有代表性的数据验证查询计划及写入成本。每次新增索引说明对应查询及收益，不为每列机械建索引。

## 迁移流程

1. 在数据变更模板列出结构、数据、兼容性和执行窗口，估算规模、锁与时长。
2. 对有旧实例并存或回滚需要的变更使用“先扩展、再迁移、后收缩”：增加可兼容字段，分批回填并核对，应用切换后再安排删除旧字段。
3. 使用接近生产规模的数据演练；记录失败中断、继续执行和恢复行为。脚本重跑要求需明确，禁止假定所有 DDL 可事务回滚。
4. 发布时只允许受控迁移执行者运行；迁移与应用版本分别记录。完成后核对数量、金额汇总、抽样业务记录及关键索引。
5. 删除或不可逆转换必须说明恢复来源和最长恢复时间。应用回滚不自动等于数据库回滚；恢复备份可能丢失新写入，须明确业务处置。
