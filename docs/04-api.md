# 04 REST／JSON 接口契约

[返回首页](../README.md)

以下字段和默认值为本团队统一约定。接口按 OpenAPI 3.1 描述并与代码共同维护；既有项目迁移可通过兼容层与有期限的例外实施。

## 强制规则

| 编号 | 适用 | 执行要求 | 检查与证据 | 责任 |
| --- | --- | --- | --- | --- |
| API-001 | 所有对外 HTTP 接口 | 路径默认 `/api/v1/{resources}`，资源名为英文复数 kebab-case；字段 lowerCamelCase；明确方法和权限 | 契约检查、评审 | 接口负责人 |
| API-002 | 接口新增或变更 | 契约先评审；说明请求、响应、身份、数据范围、错误、副作用与示例，契约与实现同步 | OpenAPI 文件、契约测试 | 接口负责人 |
| API-003 | 普通 JSON 响应 | 使用统一响应体，按实际结果设置 HTTP 状态；业务码为稳定字符串，不向外暴露堆栈和实现细节 | 响应与错误契约测试 | 后端负责人 |
| API-004 | 集合查询 | 使用统一分页；过滤与排序字段白名单；强制页大小上限；稳定排序包含唯一字段 | 边界、分页和注入测试 | 开发者 |
| API-005 | 标识符、金额、时间 | 业务 ID 以字符串传输，金额以十进制字符串传输并声明币种；时间点带时区、响应默认 UTC；纯日期单独表示 | 序列化与前端契约测试 | 前后端负责人 |
| API-006 | 可重复触发的写操作 | 明确幂等语义、键范围、保留期、请求指纹、并发和重放行为；不依赖前端按钮禁用 | 重复和并发测试 | 后端负责人 |
| API-007 | 接口兼容与废弃 | 新增字段需有兼容默认；改变语义、删除字段或收紧约束须评估消费者并提供迁移版本和截止日期 | 变更比较、消费者确认 | 接口负责人 |
| API-008 | 文件、流、批处理 | 明确媒体类型、大小、超时、权限、部分失败、断开与资源回收；禁止强行套用普通 JSON 包装 | 专项契约与安全测试 | 接口负责人 |
| API-009 | 并发更新 | 在可能丢失更新的场景使用版本或等效并发控制；冲突返回 409 并提供可恢复提示 | 并发冲突测试 | 后端负责人 |

## 响应与错误

```json
{
  "code": "0",
  "message": "success",
  "data": { "id": "9007199254740993", "status": "CREATED" },
  "traceId": "8b83ecf2d7a54ea4a9bac3c4d621fb39"
}
```

```json
{
  "code": "COMMON.VALIDATION_FAILED",
  "message": "请求参数不符合要求",
  "data": { "errors": [{ "field": "quantity", "reason": "必须为 1 至 100 的整数" }] },
  "traceId": "8b83ecf2d7a54ea4a9bac3c4d621fb39"
}
```

普通响应四个字段必需：成功 `code` 为 `"0"`；失败为非零字符串，错误码采用 `模块.原因`，例如 `ORDER.VERSION_CONFLICT`。`message` 供人阅读，客户端不得据此分支；没有业务数据时 `data` 为 `null`。校验错误的字段路径放在 `data.errors`，其他错误默认 `data: null`。`traceId` 由服务端生成或验证可信上游标识后传播，不作为认证凭据。

| HTTP 状态 | 团队用法 |
| --- | --- |
| 200 | 查询或更新成功 |
| 201 | 创建成功；返回 `Location` 与创建结果 |
| 202 | 已受理异步处理；返回任务标识和查询方式 |
| 204 | 成功且无响应体；不使用 JSON 包装 |
| 400 | JSON 无法解析、字段格式／范围错误或缺少必需请求头 |
| 401 | 未认证、凭证无效或已过期 |
| 403 | 已认证但无操作权限 |
| 404 | 资源不存在；项目可对不属于当前身份的数据同样返回 404 |
| 409 | 版本冲突、状态冲突或幂等键冲突 |
| 413 | 请求体或文件超过限制 |
| 415 | 不支持的请求媒体类型 |
| 429 | 触发限流；可提供 `Retry-After` |
| 500／503 | 内部错误／暂不可用；响应不包含内部详情 |

代理生成的 HTML 或无内容错误可能无法满足包装格式，客户端必须有安全降级提示；应用可控错误统一转换。GET 不产生业务写副作用；PUT 的重复请求应保持同样业务效果；PATCH 的具体更新语义须在契约中说明；DELETE 重复调用的状态码策略在接口中固定。

## 分页和数据表示

请求：`GET /api/v1/orders?page=1&pageSize=20&sort=createdAt,desc`。`page` 为从 1 开始的整数；`pageSize` 默认 20、范围 1～100。非法值返回 400，不静默截断。排序须追加唯一 ID 作为稳定次序。项目需设置深分页上限；大数据场景可另行定义游标分页契约，不能让一个接口默默切换两种语义。

```json
{
  "code": "0",
  "message": "success",
  "data": { "items": [], "total": 0, "page": 1, "pageSize": 20 },
  "traceId": "8b83ecf2d7a54ea4a9bac3c4d621fb39"
}
```

`total` 为非负安全整数，定义为当前筛选条件匹配的总数；空页返回空数组。ID 即使当前值较小也统一传字符串。金额示例 `"25.00"`，币种示例 `"CNY"`，精度与舍入由业务契约登记。时间点示例 `2026-11-21T02:00:00Z`；日期示例 `2026-11-21`，不隐式附加时区。JSON 不使用 NaN 或 Infinity。

## 幂等契约基线

需要幂等的创建操作使用 `Idempotency-Key`，由客户端为一次业务意图生成并在结果未知的重试中复用。键限制为 8～128 个 ASCII 字母、数字、下划线或连字符。范围绑定“可信租户／调用者＋操作＋键”，请求指纹使用校验、规范化后的业务载荷，避免仅由 JSON 字段顺序引起差异。

默认保留 24 小时；项目必须根据最长重试窗口和业务风险登记调整。数据库唯一约束或等效原子机制保证并发互斥。相同键与相同载荷返回原业务结果，响应体 `traceId` 使用本次请求标识；相同键不同载荷返回 409。仍在处理时返回 409 `COMMON.REQUEST_IN_PROGRESS`，并提供安全重试提示。

结果未知时先查明提交状态，不允许直接重复执行。幂等记录与业务写入需具备原子一致性；未产生副作用且确定已回滚的失败才允许重新执行。超过保留期不能保证仅靠键去重，重要业务还需唯一业务编号、状态机或对账。重放仍需验证当前身份、权限及资源可见性。
