# 02 Java 开发规范

[返回首页](../README.md)

基线为阿里巴巴《Java 开发手册（黄山版，2022-02-03）》。手册中的强制条款全部纳入项目检查范围；推荐、参考条款按项目基线采用。下表为团队规则映射，不替代完整手册，也不使用手册序号冒充工具规则号。涉及特定 JDK 或框架的条款，先验证适用性并记录替代实现。

## 自动检查与人工评审分工

| 手册范围 | 建议自动检查 | 必须补充的人工检查 |
| --- | --- | --- |
| 命名、格式、部分注释 | P3C／PMD、Checkstyle 或等效规则；格式工具与规则一致 | 命名是否准确表达业务、注释是否真实 |
| OOP、集合、异常、部分并发 | 静态分析、编译告警、单元测试 | 对象职责、空值契约、线程安全、业务错误处理 |
| 数据库与 ORM | SQL 审核、迁移检查、集成测试 | 索引效果、事务边界、并发一致性、数据库版本差异 |
| 安全与工程结构 | 依赖及密钥扫描、依赖关系检查 | 资源授权、敏感信息、模块归属、架构取舍 |
| 单元测试、设计规约 | 测试执行与覆盖率 | 用例有效性、边界选择、设计是否解决实际问题 |

P3C 等工具仅自动覆盖部分手册条款。项目需在技术基线中记录每类检查的工具、版本、入口、对应手册主题与未覆盖项。工具候选不构成指定选型；首次接入用包含已知违规的样例验证规则确实运行，升级 JDK 或插件时复查。

## 正反例

禁止二进制浮点构造金额，也不要通过修改 DTO 字段顺带完成业务校验。

```java
// 错误：二进制浮点输入不能可靠表达十进制金额。
BigDecimal price = new BigDecimal(0.1);

// 正确：精度、舍入与币种规则由领域明确规定。
BigDecimal unitPrice = new BigDecimal("12.50");
BigDecimal totalAmount = unitPrice.multiply(BigDecimal.valueOf(quantity));
```

```java
// 错误：异常被吞掉，调用方无法判断实际结果。
try {
    repository.save(order);
} catch (Exception exception) {
    return null;
}

// 推荐：在已定义的边界转换异常并保留原因；由统一出口生成安全响应。
try {
    repository.save(order);
} catch (PersistenceException exception) {
    throw new OrderStorageException("Order persistence failed", exception);
}
```

这里的异常类型由项目实际存储适配层定义；示例是规则说明，不是对某个框架的依赖。日志禁止打印密码、令牌、完整证件号或未脱敏业务正文；错误堆栈只留在受控服务端。

## 推荐与可选实践

- 推荐依赖注入、不可变值对象、显式边界校验，避免静态全局可变状态。
- 推荐按业务模块编写测试；将领域规则与基础设施隔离，使核心规则无需启动完整应用即可测试。
- 新语言能力、虚拟线程、响应式模型等可选，采用前验证 JDK、驱动、监控、资源限制和团队维护能力。
