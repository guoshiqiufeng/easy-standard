# 订单测试与发布样例

这些是待执行的验证方案，未记录任何实际业务测试通过结果。真实项目将用例落地到其选定工具，执行后填写[测试报告](../../templates/10-test-report.md)。

## 测试矩阵

| 编号 | 场景与操作 | 必需断言 | 层次 |
| --- | --- | --- | --- |
| TC-ORDER-001 | 用户 A 购买 2 件单价 12.50 的商品 | 201、code="0"、金额 "25.00"、ID 为字符串，数据库恰好一笔 | 单元＋集成＋契约 |
| TC-ORDER-002 | 未登录、无创建权限、用户 B 查询 A 的订单 | 分别 401、403、404；没有订单详情泄露 | 安全＋契约 |
| TC-ORDER-003 | 同用户、同键、同载荷顺序重试 | 201、同订单 ID 和金额，traceId 对应当前请求，无重复写入 | 集成 |
| TC-ORDER-004 | 同用户同键同时发起 10 个请求 | 最多一笔订单；201 或处理中的 409；随后重试得到同一结果 | 数据库并发 |
| TC-ORDER-005 | quantity 为 0、101、1.5 或价格精度异常 | 参数错误 400；服务端无效报价为安全服务错误；无业务写入 | 单元＋集成 |
| TC-ORDER-006 | 已使用的键改成不同 quantity | 409 COMMON.IDEMPOTENCY_CONFLICT；原订单不变 | 集成＋契约 |
| TC-ORDER-007 | 提交完成但客户端超时；提交前数据库失败 | 前者同键查回原结果；后者确认回滚，无半条幂等记录或订单 | 故障注入 |
| TC-ORDER-008 | 多用户混合列表、空页、页大小 101、page 1001 | 仅本人数据；空数组；超限 400；排序稳定 | 集成＋契约 |
| TC-ORDER-009 | 大 ID、金额与 UTC 时间展示 | ID 无精度丢失，金额两位；显示时区符合页面规则 | 组件＋契约 |
| TC-ORDER-010 | 慢请求后发先至、卸载、失败后重试 | 旧响应不覆盖，卸载不更新，加载／错误／空状态清楚 | 组件＋E2E |
| TC-ORDER-011 | 数据库不可用或实例退出 | 受控超时与错误，不泄漏内部信息，不产生不确定重复写入 | 集成＋运行 |
| TC-ORDER-012 | 上线迁移、应用回滚、从备份恢复 | 新旧兼容；回滚保留已写数据；恢复实际 RPO／RTO达登记目标 | 发布＋演练 |
| TC-ORDER-013 | 用户身份或权限改变后重放；24 小时过期键 | 重放重新授权；过期行为符合契约且 UI 提醒核对 | 安全＋集成 |
| TC-ORDER-014 | 指定负载与数据量下查询 | 按 README 的环境、区间测量 P95、错误率与容量，不只看平均值 | 性能 |

每条失败用例需有负面控制：能够识别缺陷，而不是仅镜像代码输出。所有数据使用隔离测试用户，测试结束清理；故障注入不得指向生产。

## 发布与数据变更样例

1. 选择并验证数据库、ID 策略及建表迁移；确认唯一约束、列表索引与幂等过期清理。迁移独立执行且记录版本。
2. CI 完成代码规范、测试与扫描，固定前后端镜像摘要、配置版本和迁移版本；预生产使用同一制品。
3. 首次上线前完成备份恢复演练和 10 万订单规模验证。本例单机 Compose 发布采用维护窗口；项目必须填入真实资源、命令、联系人与批准记录。
4. 发布前保存旧制品摘要、配置和备份位置；先扩展数据结构，再更新应用。旧版本不使用新表时可保留新表回滚应用，不能删除新订单数据。
5. 冒烟验证登录、创建、同键重试、列表与详情；使用指定验收身份和对象并登记清理，不能重复制造真实交易。
6. 本样例停止阈值：关键冒烟任一失败立即停止；就绪 5 分钟未通过则停止。扩大流量后连续 5 分钟服务端错误率 > 1%，或列表 P95 > 1000ms 且每分钟至少 100 个样本，启动回滚评估；低流量依赖业务探测与日志确认。
7. 回滚前确认当前结构兼容旧应用；恢复旧镜像与对应配置，重新验证关键路径。数据库不可逆时按已批准前向修复或备份恢复执行，并核对期间新增写入。
8. 观察 30 分钟并记录实际版本、指标、异常与结论；未达恢复目标时不能只将阈值改大，需要整改或重新评审架构。

## 运维样例

关键监控：创建成功率、冲突类型、创建／查询 P95、数据库连接与锁、幂等记录增长、磁盘、备份新鲜度。用户 ID 与订单 ID 留在受控日志，不作为指标标签。

本样例 RPO 24 小时可采用至少每日备份并保留独立故障域副本；实际备份调度要留出失败重试空间并监控可恢复数据时点。季度演练在隔离环境还原数据库、配置及恢复凭据，验证订单数量、金额汇总、用户隔离和幂等结果，记录从假定故障到业务恢复的耗时。
